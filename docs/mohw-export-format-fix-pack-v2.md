## 本次重現的問題

| 問題 | 更新版實際結果 | V2 修正 |
|---|---|---|
| ISO 日期正規式未限定結尾 | `1959-06-15ERROR`、`1959-06-150` 都被截成 `048/06/15` 並通過 | 完整比對日期字串，非法尾綴留原值給 Validator 攔下 |
| 電話刪除所有非數字字元 | 含英文字母的手機會刪字母後變成另一個合法號碼 | 只移除空白、括號、連字號；字母與分機符號不刪除 |
| 電話沒有內容格式驗證 | `phone=abc` 或 `mobile=0911`，即使另一欄空白仍通過 | 加入國內手機／市話格式檢查；遺失前導 0 回原資料確認，不自動猜補 |
| 身分證驗證器先清理符號 | 輸出 `A-123456789`，驗證卻以去掉連字號的值通過 | 對實際輸出先檢查 1 英文＋9 數字，再做檢查碼驗證 |
| 未完成訪視只略過 AC:CK | 拒訪且未填 CL/CM/CN 仍因同意與簽名欄被擋 | 按範本總說明「住宅類型起忽略」處理 AC:CN；未完成訪視不帶入歷史問卷、同意或簽名答案；訪查人 CO:CY 保留 |
| 寫入後未回讀 | 寫入前的陣列通過不代表 Sheet 實際型態相同 | flush 後回讀 getValues/getFormulas，檢查每格型態與原文一致才取得 XLSX |
| 部分錯誤路徑留下暫存 Sheet | 寫入或建立 Drive 檔案失敗時不一定清理 | finally 清理暫存檔；HTTP 200 但非 ZIP 回應也擋下 |

ISO timestamp 額外支援：明確附 Z 或時區偏移的完整 timestamp，先檢查日期存在，再依 Asia/Taipei 取日期。例如 `1959-06-14T16:00:00Z` 對應臺灣的 `048/06/15`。沒有時區或帶不明尾綴的 timestamp 不猜測，要求回原資料確認。

## 村里內容的額外風險

目前 mergeInputs 會呼叫 applyVillageAutoFix；其邏輯可能用居住地址或居住村里改寫戶籍村里。這不能由「通過村里允許值」證明真實內容正確，尤其戶籍地址與居住地址不同時。

V2 在生活關懷表匯出 Mapper 中停止呼叫此自動改寫，保留既有 Validator 對永和村里的檢查。村里不合法時回報給人員修正來源資料。V2 不修改 OfficialTemplate 內的村里方法，也不改其他使用者流程。mergeInputs 改為複製答案物件，避免組合輸出時改動呼叫端原始物件。

## 規則界線：不能只靠這份範本確認的部分

1. 電話採國內市話 9–10 碼或手機 09 開頭 10 碼。這是配合範本例子及本專案國內聯絡資料採用的格式政策，範本本身沒有明列完整電話正規式。國際電話、特殊短碼、分機如需使用，應先確認中央系統支援；V2 會回報而不改號碼。
2. 範本總說明表示非完成訪視的問卷「住宅類型起」被忽略。V2 將同屬問卷末段的同意及簽名欄 CL:CN 一併留空，絕不自動填同意。如中央系統另規定這三欄仍必填，應依中央規定調整略過範圍與實際訪視紀錄。
3. 原 Validator 的「只要出現任一訪查人欄就要求該組五欄完整」及訪查人身分證檢查碼仍保留。提供的說明對訪查人逐欄必填標記不完全一致，不能單憑此檔確認中央是否同樣要求整組完整。
4. 村里對照仍沿用專案現有名冊，未向外部驗證名冊是否最新。
5. 本平台 registryIds 相符不能證明中央系統已建立個案；需要中央實際匯入結果。
6. 本地文字寫入模擬不能證明 Google 最終 XLSX 的 quotePrefix metadata 或中央解析結果；重新匯出後仍須讀檔確認。
